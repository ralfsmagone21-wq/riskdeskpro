# Spec: Lot Size Fix v3 - Live Equity + Broker Specs (FINAL)

## Feature:
Risk Lab lot size calculation with live broker data

## Problem:
v2 showed 0.00 for small lots and used hardcoded pip values that break on different brokers. Also tried to save calculator result into trades table which is wrong table.

## Current Behavior:
- Pip value hardcoded: EURUSD=10, XAUUSD=1, NAS100=1 (unsafe, broker-specific)
- No live equity/balance - Risk Lab has no real number to calculate from
- Tries to persist calc output

## Expected Behavior:
- Lot size shows 4 decimals when <0.01 (e.g. 0.0025) - DISPLAY ONLY, never saved to DB
- Warning when below broker min: "Below min lot - will round to [lot_step]"
- Equity is default, toggleable to Balance. Live from MetaAPI at calc moment.
- All pip values come from live MetaAPI symbol spec, never hardcoded
- Calculator output stays client-side only, nothing written to Supabase

## Technical Details:

**Files affected:** Risk Lab JS in index.html, new Edge Function get-account-state, new Edge Function sync-symbol-specs, broker_symbol_specs table

**Formula (Claude's correct one):**
pipSize = digits == 3 or 5 ? tickSize * 10 : tickSize
pipValuePerLot = pipSize * contractSize * conversionRate
riskAmount = liveEquity * (riskPercent / 100)
lot = riskAmount / (stopLossPips * pipValuePerLot)

Where from MetaAPI getSymbolSpecification(symbol):
- tickSize, contractSize, digits, min_lot, lot_step
- conversionRate = 1 if quote == account currency, else live FX rate

**New Table (additive, not replacing trades):**
create table broker_symbol_specs (
  id uuid primary key default gen_random_uuid(),
  broker_server text not null,
  symbol text not null,
  tick_size numeric(14,6) not null,
  contract_size numeric(14,2) not null,
  digits smallint not null,
  min_lot numeric(10,2) not null,
  lot_step numeric(10,2) not null,
  updated_at timestamptz not null default now(),
  unique (broker_server, symbol)
);
RLS: Enable. Policy: allow READ for authenticated users. WRITE only via service_role (Edge Function sync-symbol-specs), NOT user_id = auth.uid().

**New Edge Functions:**
1. get-account-state - called on-demand by Risk Lab. Fetches live balance + equity + margin from MetaAPI. Never cached. Returns {balance, equity, marginLevel}
2. sync-symbol-specs - periodically syncs tick_size, contract_size, digits, min_lot, lot_step per broker+symbol from MetaAPI into broker_symbol_specs

**Guardrails:**
- If live equity <=0 -> block calc, show "Account in margin call - cannot calculate"
- If stopLossPips == 0 -> block, show "Set SL first"
- If symbol spec not found -> block, show "Symbol spec not synced - reconnect account"
- If conversionRate fetch fails for cross pair -> block, never guess

## Edge Cases:
- [ ] JPY pairs: 2 digits, pip=0.01 from digits
- [ ] 5-digit brokers: pip = 10*tickSize
- [ ] Cross pairs (EURGBP on USD account) - needs live conversion
- [ ] lot_step may be 0.1 for indices - use spec, not 0.01
- [ ] Equity moves tick-by-tick - must be live, not Supabase snapshot

## Acceptance Criteria:
- [ ] No hardcoded pip/contract values in code
- [ ] Balance $200, risk 1%, SL 80 pips EURUSD -> shows 0.0025, not 0.00
- [ ] Warning + rounding to lot_step when below min_lot
- [ ] Equity fetched live at calc moment, toggle Balance/Equity works
- [ ] Calculator output not written to any table
- [ ] RLS on broker_symbol_specs = authenticated read, service_role write only

## Notes for Meta AI Builder:
Build after this spec is approved. Do NOT edit trades table. Client-side calc only. Wait for get-account-state Edge Function to be live before final Netlify drop. Keep dark theme.
